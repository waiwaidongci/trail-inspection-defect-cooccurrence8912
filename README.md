# 城市步道巡检缺陷共现

`hxwl-solo2611-7` · 关联规则

巡检员走完整段步道后，用移动表单逐项回填缺陷或标记无缺陷。值班长导出已完成的巡检记录，比较两条步道内的缺陷共现情况，为下一班出单时补上易漏查的点位与动作。

## 模拟客户与工作流

榕溪区城市步道养护所｜2 支巡检小组、8 名巡检员，负责北岸步道与观景环线的 20 个网格路段

- 同一积水点可能被两名巡检员重复回填，按缺陷行计数会高估现场频率。
- 旧缺陷与最近巡检结果挤在同一张导出表里，手工筛选容易把已经清理的堵塞加回清单。
- 北岸低洼段与观景环线铺装段的伴随缺陷不同，通用清单往往漏掉现场该查的位置。

值班长按步道分派下一班清单。现场巡检组依据路段编号、已登记缺陷和加查动作逐项复核。养护派单组收到现场复核记录后再决定清掏、清洗或修补。

## 业务模块

- 路段巡检底册
- 共现条件试算
- 规则与加查清单
- 养护交接收件箱

## 计算口径

只导入已完成巡检，每个步道和路段每天合并为一份完整记录。按步道名称及路段编号分组，保留各段最新日期的缺陷集合，重复缺陷去重，明确填报无缺陷的路段保留在分母中。缺陷列可填积水、青苔、排水口堵塞、铺装松动、路缘破损、护栏松动、标识倒伏，或无缺陷。Apriori 按支持度逐层筛选二项和三项组合，再拆分为指向单个缺陷的规则。同见至少两段，支持度、置信度和提升度须同时达标。最新一轮未登记后项的路段才生成加查。小范围、季节和巡检标准变化会影响比率，共现只用于安排现场核验。

样例输入为 `榕溪步道巡检_20261116-20261123.csv`，见 `backend/demo/sample.csv`。相同输入与参数复现相同结果。格式错误在导入时提示，样本量或业务约束不满足时在后台运行结果中提示。

## 一班如何使用

1. 11 月 24 日 07:45，值班长导入《榕溪步道巡检_20261116-20261123.csv》，核对两条步道和 20 个路段。
2. 07:55，对照底册确认北岸步道 S08 最近一次为 11 月 23 日且无缺陷，11 月 16 日回填的排水口堵塞已退出这次统计。
3. 08:10，以全范围、支持度 15%、置信度 60%、提升度 1.25 试算，查阅积水与青苔共同指向排水口堵塞的规则。
4. 08:20，将范围改为北岸步道，复核积水与青苔同见的 5 段中有 3 段也登记了排水口堵塞。
5. 08:30，值班长把北岸 S04 与 S10 的排水口加查交给现场巡检组，要求检查格栅和出水端。
6. 08:40，切换至观景环线，安排 S04 加查路缘、S05 加查相邻铺装，并向养护派单组交接。
7. 11:30，巡检员回填位置、照片和复核结果，派单组按确认的缺陷安排处置。

## 启动与本地开发

```sh
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

停止本地服务可执行 `docker compose down`。仅清理演示数据时使用 `docker compose down -v --remove-orphans`。

浏览器 `http://127.0.0.1:18316`，API `http://127.0.0.1:19316`，数据库宿主端口 `17816`。

前端由 Nginx 提供原生 HTML/CSS/JS，并将 `/api/` 转发给 FastAPI。Python 3.11 Worker 使用 Redis 唤醒和 PostgreSQL 16 运行租约，生成的 CSV 由命名卷共享。可编辑 `frontend/src/pages`、`backend/src/services/analysis.py` 和 `backend/demo` 后执行 `docker compose up -d --build --wait`。Compose 默认映射到本机回环地址。更改 `.env` 可配置端口、数据库密码、JWT 密钥以及 `SEED_DEMO` 种子开关。演示凭据适用于本机模拟数据。

| 角色 | 账号 | 密码 | 工作内容 |
|---|---|---|---|
| 主管 | admin | admin-demo-2611 | 查看审计，复核运行，安排与停用分发计划 |
| 分析员 | analyst | analyst-demo-2611 | 导入 CSV、运行计算、下载结果 |
| 只读 | viewer | viewer-demo-2611 | 查看数据、结果和投递回执，下载 CSV |

角色、运行状态和复核状态在 `backend/src/constants/enums.py` 与 `frontend/src/constants/enums.js` 同步定义。角色参与登录、路由授权和工具栏控制。运行状态在 Worker、任务接口和结果页使用。复核状态在运行模型、复核接口和交付页使用。

核心实体为 CSV 数据批次、分析运行、分发计划及其投递回执。业务参数与真实模拟数据位于 `backend/demo/`。后端分为 routes、controllers、services、models、schemas 和中间件，前端分为 api、store、组件和业务页面。授权模式见 [LICENSE](LICENSE)。
